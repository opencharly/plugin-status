# 2026.331.0916 — feat(plugin-status)!: follow the spec module's Android removal

## Summary

The spec module's Android retirement (spec `v0.2026331.808`) removed the `SubstrateAndroid` constant and the `kind:android` substrate. This repo's `candy/plugin-status` still referenced the constant, so the module did not compile against the new contract:

```
$ cd candy/plugin-status && go build ./...
./nested_tree.go:163:15: undefined: spec.SubstrateAndroid
```

This change removes the Android surface from the code, tests and the repo's own documentation:

- `nestedChildKind`: delete the `case "android": return spec.SubstrateAndroid` arm; the surviving generic arms (`vm`, `kubernetes`, `local`/`host`, default `pod`) are unchanged.
- `nested_tree_test.go`: the fixture used a `pod → android` topology only as a convenient nested shape; it is retargeted to a live `pod → pod` topology (`check-nested-pod` with `worker` / `worker-net` children), keeping the same declared-tree, MatchKeys-order and live-probe assertions with `spec.SubstratePod`.
- `overlay_golden_test.go`: the byte-parity golden used an Android child as a convenient claimed row; it is retargeted to a live nested-pod child. The claim/inherit/synthesize semantics and the golden's exact-byte assertion are unchanged.
- Go comments that named android among the substrate set are corrected.
- **R5 docs sweep, in this PR:** the owning `charly-status` skill (`.agents/skills/charly-status/SKILL.md`, the body behind the `charly-status-skill` node), `README.md`, and the candy `description:` are swept from the retired five-substrate claim to the four live substrates (pod/vm/kubernetes/local); the nested examples are retargeted to a pod-in-pod topology and the android collector / readiness-poll / adb references are removed.

Dependencies pinned to the merged prerequisites: spec `v0.2026331.808`, sdk `v0.2026331.837`.

The cause is a removed contract constant, so the spec artifact settles the candidates:

- **A — delete the arm and retarget the fixtures (winner).** The new spec declares no replacement for `SubstrateAndroid` and no `kind:android` word; a nested child now classifies to a live substrate (`pod`, `vm`, `kubernetes`, `local`). Deleting the arm keeps `nestedChildKind` total via its default `pod` arm, and retargeting the fixtures to `pod → pod` preserves every assertion and the exact-byte golden.
